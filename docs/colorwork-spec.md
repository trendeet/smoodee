# 컬러워크 (ColorWork) 스펙 문서

> `docs/prd.md`(제품 PRD, §2 S2 / §7 T1 / §8.3)와 실제 구현 코드를 대조한 현행화 스펙입니다.
> PRD에서는 "컬러워크(ColorWalk)"로 표기되어 있으나 실제 코드/라우트는 `colorwork`로 통일되어 있습니다.

- 프론트엔드: `frontend/src/features/colorwork/`, 라우트 `frontend/src/app/(main)/colorwork/page.tsx`
- 백엔드: `backend/src/main/java/com/smoodee/personal/` (`ColorworkController`, `ColorworkService`)
- 진행중 탭 연동: `frontend/src/app/(main)/inprogress/page.tsx`

---

## 1. 개요

컬러워크는 로그인 여부와 무관하게 시작할 수 있는 개인용 사진 콜라주 제작 플로우다. "오늘의 무드 팔레트 선택 → 레이아웃(사진 장수) 선택 → 사진 업로드 + 프레임 디자인 → 완성/다운로드·공유" 순으로 진행되며, `/colorwork` (신규 시작)와 `/colorwork?projectId={id}` (진행중 탭에서 재개) 두 진입점이 완전히 분리된 컴포넌트(`ColorWorkFlow.tsx` / `ColorWorkResumeFlow.tsx`)로 구현되어 있다.

PRD 대비 가장 큰 차이는 **레이아웃이 2종(2x2/3x3)이 아니라 6종**이고, **프레임 색상·굵기·모서리 커스터마이징 기능이 PRD에 없던 완전 신규 기능**이라는 점, 그리고 **PRD가 명시한 "자동 저장"이 실제로는 없고 사용자가 직접 "임시저장"을 눌러야 한다**는 점이다.

---

## 2. 전체 유저 플로우

```
[신규 시작: /colorwork]
  가이드 인트로(step 0) → "사용법 알아보기" 또는 "건너뛰기"
    ├─ 알아보기: 가이드 step 1(색상)→2(레이아웃)→3(업로드+디자인)→4(결과 미리보기), 각 단계 "건너뛰기" 가능
    └─ 건너뛰기: 곧장 실제 플로우 시작
  → 실제 플로우 step 1: 팔레트 선택(3개 중 1개, 새로고침으로 재생성)
  → 실제 플로우 step 2: 레이아웃 선택 (4장/6장/9장 × 매거진형/격자형 = 6종)
  → 실제 플로우 step 3: 사진 업로드(슬롯별) + 프레임 디자인(색상/굵기/모서리)
      ├─ "임시저장" → 프로젝트 생성/저장 후 진행중(개인) 탭으로 저장됨
      └─ "완성하기" (모든 슬롯 채워야 활성화) → 캔버스 합성 → 썸네일 업로드
  → 실제 플로우 step 4: 결과 화면 (다운로드 / 공유 / 홈으로)

[재개: /colorwork?projectId={id}, 진행중 탭에서 카드 탭]
  가이드 없이 곧장 서버에 저장된 상태를 조회해 이어질 단계로 진입
  (팔레트만 있으면 레이아웃 선택부터, 레이아웃까지 있으면 업로드 화면부터 — 부분 업로드도 그대로 이어짐)
  뒤로가기는 항상 "진행중" 탭으로 돌아감(이전 스텝이 아님)
```

## 3. 화면별 상세 스펙

### 3.1 가이드 모드 (`ColorWorkFlow.tsx`, `mode === "guide"`, step 0~4)
- PRD F 요구사항 "사용법 안내 + 건너뛰기"에 대응. 실제 UI/실제 데이터를 그대로 복제한 뒤 어둡게 오버레이하고 특정 영역만 스포트라이트로 보여주는 "인터랙티브 미리보기" 형태(실제 클릭은 안 되고 `pointer-events-none`).
- 각 단계 우상단에 "건너뛰기" 버튼 상시 노출 → 클릭 시 곧장 실제 플로우 step 1로 진입(`startProject`).
- 각 단계 하단에 이전/다음 내비게이션 + 진행 점(dot) 4개.
- step 0(인트로) 문구: "일상적인 공간을 새롭게 관찰해보세요", 버튼 "사용법 알아보기" / "건너뛰기".
- step 4(가이드 마지막)에서는 "다음" 대신 "직접 만들기" 버튼으로 실제 플로우 진입.

### 3.2 실제 플로우 — 팔레트 선택 (step 1)
- 헤딩 "오늘 당신의 무드는 어떤가요?", 서브텍스트 "가장 끌리는 팔레트를 선택해주세요."
- **팔레트는 백엔드 API가 아니라 클라이언트에서 즉석 생성**(`colorworkService.shufflePalette`는 실제로 서버를 호출하지 않고 `randomHexPalettes()`로 로컬에서 3세트를 만든다 — PRD의 "새로고침 버튼으로 재생성"은 맞지만 서버 관여가 전혀 없다는 점은 PRD에 명시되어 있지 않다).
- "새로고침" 버튼으로 재생성, 카드 3개 중 1개 선택(`ColorBlockSelector`), 선택 시 "선택 완료" 버튼 활성화.
- 이 단계에서 선택한 팔레트는 **DB에 즉시 저장되지 않는다** — "임시저장" 또는 "완성하기" 시점에만 `PUT /palette/select`가 호출된다.

### 3.3 실제 플로우 — 레이아웃 선택 (step 2)
- 헤딩 "몇 장의 사진을 담을까요?"
- **PRD 대비 최대 차이점**: PRD는 "2×2(4장) 또는 3×3(9장)" 2종만 언급하지만, 실제로는 **4장/6장/9장 각각 "매거진형"과 "격자형" 2종씩 총 6종**(`G2`, `G2_GRID`, `G6`, `G6_GRID`, `G3`, `G3_GRID`)이 존재한다.
- "시작하기" 버튼은 레이아웃 선택 전엔 비활성화.

### 3.4 실제 플로우 — 업로드 + 디자인 (step 3, `ColorWorkStep3Body`)
- 상단: 뒤로가기(신규 플로우는 "레이아웃 선택으로 돌아갈까요? 업로드한 사진이 초기화돼요" 확인 모달을 거침), 채움 카운터 "{filled} / {total} 채움", 로그인 상태일 때만 "임시저장" 버튼.
- 사진 슬롯: 그리드 형태로 배치, 빈 슬롯은 카메라 아이콘 + "각 프레임을 눌러 사진을 채워주세요!" 안내. 슬롯 탭 → 파일 선택 → **크롭 모달**(`ImageCropModal`, 슬롯별 목표 비율에 맞춰 드래그 크롭) → 확정 시 슬롯에 반영.
- 디자인 컨트롤 3탭: "색상"(프리셋 5색 + 커스텀 컬러피커), "굵기"("없음"/"얇게"/"굵게"), "모서리"("직각"/"둥글게"). **PRD에는 전혀 없는 신규 기능**이며 서버 검증 없이 임의 값 저장 가능(`saveFrameStyle`가 값 검증을 하지 않음).
- **레이아웃(그리드) 변경 UI는 존재하지만 열 수 없다(§6-8 참고)**: `ColorWorkStep3Body`에 "프레임을 바꾸시겠어요? 기존에 저장된 이미지가 모두 삭제됩니다." 확인 모달과 "프레임 수 변경" 바텀시트가 구현되어 있고, `selectGrid` 호출 시 서버가 실제로 해당 프로젝트의 모든 `PersonalFrame`을 삭제하는 것도 맞다 — 하지만 이 모달을 여는 트리거(`setFrameModalStep("confirm")` 호출)가 `ColorWorkFlow.tsx`/`ColorWorkResumeFlow.tsx` 어디에도 없다. 업로드 단계에서 레이아웃을 바꾸는 유일한 실제 경로는 상단 뒤로가기(→ 레이아웃 선택 화면 자체로 돌아가는 것)뿐이다.
- "완성하기" 버튼: **모든 슬롯이 채워져야만** 활성화(`filledCount === totalSlots`) — 부분 완성 불가가 프론트 규칙. 단, **백엔드는 이 조건을 전혀 검증하지 않는다**(§6 참고, API를 직접 호출하면 빈 프로젝트도 완성 처리 가능).
- 완성 처리 중엔 "렌더링 중..." 으로 문구 변경.
- 완성 실패 시 모달: "완성하기 실패" + 사유별 안내문 두 가지 중 하나:
  - "이미지 생성에 실패했어요. 다시 시도해주세요." (캔버스 합성 실패)
  - "저장에 실패했어요. 다시 시도해주세요." (썸네일 업로드 실패)
  - (`colorworkService.complete()` 자체의 실패는 조용히 무시되고 진행이 막히지 않는다 — 즉 프로젝트 상태 전이 API가 실패해도 사용자는 계속 진행 가능)
- 임시저장 완료 모달: "임시저장이 완료되었습니다" / "저장 내용은 진행중인 활동에서 확인할 수 있습니다." / 버튼 "홈으로 이동" · "진행중인 활동".
- 로그인하지 않은 상태에서도 전체 플로우 진행 가능하지만, "완성하기" 클릭 시 실제 저장 없이 곧장 step 4로만 이동(`handleComplete`에서 `isLoggedIn`이 false면 API 호출 없이 바로 결과 화면). 안내 문구: "로그인하면 보관함에 자동 저장돼요" (로그인 링크 포함).

### 3.5 실제 플로우 — 결과 (step 4, `ColorWorkStep4Body`)
- 최종 합성 이미지 미리보기(HTML5 canvas로 클라이언트에서 렌더링, 서버 렌더링 아님), 캡션 "#컬러워크 #{팔레트이름} #{장수}cuts".
- 버튼: "다운로드"(모바일은 `navigator.share`로 사진첩 저장 유도, 데스크톱은 일반 다운로드), "공유"(Web Share API 지원 시에만 동작, 미지원 브라우저에서는 실패해도 안내 없이 조용히 무시됨), "홈으로".
- 로그인 상태면 0.4초 후 페이드인되는 안내: "보관함에 저장되었습니다" + "보관함 확인하기" 버튼(`/recent`로 이동).
- **PRD는 "기본 Story 9:16 다운로드"를 명시하지만, 실제 출력 이미지는 9:16 고정이 아니라 선택한 레이아웃마다 다른 종횡비**(예: `G2`는 3:2, `G6_GRID`는 2:3, `G3`는 4:3 등)로 생성된다. PRD의 "옵션: Feed 4:5/1:1"에 해당하는 규격 선택 UI는 없다.
- **PRD가 말한 "디자인 프리셋(여백/타이포/스티커/필름 프레임) 자동 적용"에 해당하는 기능이 없다** — 실제로는 사용자가 직접 고른 배경색/테두리 굵기/모서리만 적용되고, 스티커나 타이포그래피 오버레이는 전혀 없다.

### 3.6 재개 플로우 (`ColorWorkResumeFlow.tsx`, `/colorwork?projectId={id}`)
- **가이드 단계가 없다** — 곧장 서버 상태를 조회(`GET /{projectId}`)해 이어질 스텝을 계산한다:
  1. `initialStep` 파라미터(URL의 `?step=4`)와 `gridType`이 모두 있으면 그 스텝으로
  2. 아니면 `gridType`이 있으면 step 3(업로드, 기존 업로드분 그대로 복원)
  3. 아니면 `paletteSeed`가 있으면 step 2(레이아웃)
  4. 아니면 step 1(팔레트)부터
- 상태 조회 실패(프로젝트 없음/권한 없음 등) 시 **에러 문구 없이 조용히 `/inprogress`로 돌아간다.**
- 뒤로가기는 (신규 플로우와 달리) **항상 `/inprogress`로 이동** — 이전 스텝으로 돌아가는 게 아님.
- 업로드된 프레임은 `/api/v1/assets/{assetId}/stream`을 fetch해 blob으로 변환 후 표시(실패 시 presigned URL로 폴백).
- 이 화면의 "임시저장" 버튼은 신규 플로우와 달리 실질적으로 아무 것도 저장하지 않는다(이미 각 액션마다 즉시 서버에 반영되고 있어서) — 그냥 "저장됨" 확인 모달만 띄우는 용도.

### 3.7 진행중(개인) 탭 진입점 (`frontend/src/app/(main)/inprogress/page.tsx`)
- 헤딩 "진행 중인 활동", 그룹/개인 서브탭(`개인` 선택 시 컬러워크 프로젝트 노출).
- 카드 탭 → `router.push(\`/colorwork?projectId=${id}\`)` 로 재개 플로우 진입.
- 카드 진행률 바: `filledFrames`/`totalFrames` 기준(예: "3/9").
- 빈 상태: "진행 중인 활동이 없어요." / "새로운 활동을 시작해보세요!"
- 롱프레스 또는 "선택" 버튼으로 다중 선택 → "삭제" (확인 모달: "프로젝트를 삭제할까요?" / "삭제하면 되돌릴 수 없어요.").

## 4. API 명세 (BASE: `/api/v1/personal/colorwork`)

| Method | Path | 설명 | 인증 |
|---|---|---|---|
| POST | `/projects` | 프로젝트 생성 (status=INIT) | 선택적(§6 참고) |
| PUT | `/{projectId}/complete` | 완성 처리 (status→DONE, **필드 채움 검증 없음**) | 선택적 |
| PUT | `/{projectId}/howto-seen` | 가이드 시청 여부 저장 | 선택적 |
| POST | `/{projectId}/palette/shuffle` | (프론트에서 실제로는 호출 안 함 — 클라이언트에서 자체 생성) | 선택적 |
| PUT | `/{projectId}/palette/select` | 팔레트 확정 저장 | 선택적 |
| PUT | `/{projectId}/grid` | 레이아웃 선택 (**기존 프레임 전체 삭제**) | 선택적 |
| PUT | `/{projectId}/frames/{index}` | 슬롯에 에셋 바인딩 | 선택적 |
| PUT | `/{projectId}/frame-style` | 프레임 색상/굵기/모서리 저장 (값 검증 없음) | 선택적 |
| PUT | `/{projectId}/thumbnail` | 완성 썸네일 업로드(multipart) | 선택적 |
| GET | `/{projectId}` | 현재 진행 상태 조회 | 선택적 |

관련 엔드포인트(다른 컨트롤러):
- `POST /api/v1/projects/{projectId}/assets` — 사진 업로드
- `PATCH /api/v1/projects/{projectId}/title` — 임시저장 시 제목 설정("진행중인 템플릿을 확인해주세요")
- `GET /api/v1/projects?type=PERSONAL&tab=IN_PROGRESS` — 진행중 탭 목록

## 5. 데이터 모델

- **PersonalColorworkConfig** (프로젝트당 1행): `paletteSeed`, `selectedPaletteJson`(hex 배열 JSON), `gridType`, `howtoSeen`, `thumbnailS3Key`, `frameColor`, `frameThickness`, `cornerStyle`
- **PersonalFrame** (바인딩된 슬롯당 1행, 자동증가 PK): `projectId`, `frameIndex`, `assetId` — **빈 슬롯은 행 자체가 없다**(에셋이 실제로 바인딩된 슬롯만 행 생성)
- **GridType** enum: `G2, G2_GRID, G6, G6_GRID, G3, G3_GRID`
- **ProjectStatus**(컬러워크 한정): `INIT`(생성 직후) → `UPLOADING`(레이아웃 선택 시) → `DONE`(완성 처리 시)

## 6. 발견된 이슈 / 확인 필요 사항

1. **[백엔드 인가 누락 — 확인 필요]** `ColorworkService`의 모든 메서드는 `if (userId != null)`일 때만 소유자 검증(`requireOwner`)을 수행한다. 즉 **비로그인(익명) 요청은 `userId`가 `null`이라 소유자 검증 자체가 통째로 스킵되어, URL의 `projectId`만 알면 다른 사람의 프로젝트를 조회/수정할 수 있는 것으로 보인다.** 실제 악용 가능성 및 의도된 설계인지(비로그인 사용자도 게스트로 자기 프로젝트를 만들 수 있게 하려는 설계와 결합되면서 생긴 부작용일 가능성) 백엔드 팀 확인이 필요하다.
2. **[완성 조건 미검증]** "완성하기"가 모든 슬롯을 채워야 활성화되는 건 프론트 전용 규칙이고, 백엔드 `PUT /complete`는 프레임 개수를 전혀 검증하지 않는다. API를 직접 호출하면 빈 프로젝트도 `DONE` 처리 가능.
3. **[PRD 불일치 — 자동저장]** PRD(§8.3)는 "나가기 시 진행중 저장(자동 저장 + 명시적 저장)"을 요구하지만, 실제로는 자동저장이 전혀 없다 — 사용자가 "임시저장"을 누르지 않고 이탈하면 프로젝트 자체가 생성되지 않아 아무 것도 남지 않는다. `beforeunload` 경고("페이지를 벗어나시겠습니까?" 류 브라우저 기본 확인창)만 있을 뿐 실제 자동 저장 로직은 없다.
4. **[PRD 불일치 — 출력 규격]** PRD가 명시한 "Story 9:16 고정 다운로드"가 아니라 레이아웃별 가변 비율로 출력된다. 4:5/1:1 옵션도 없다.
5. **[PRD 불일치 — 디자인 프리셋]** PRD의 "타이포/스티커/필름 프레임 자동 적용"은 구현되어 있지 않고, 대신 사용자가 직접 고르는 프레임 색상/굵기/모서리 옵션으로 대체되어 있다.
6. **[죽은 코드]** `ColorWorkResumeFlow.tsx`에 실제로는 호출되지 않는 `buildCanvasUnused` 함수(약 180줄)가 남아있다 — 실제 사용되는 `buildCanvas`와 로직이 거의 동일해 보이며, 정리 대상으로 보인다.
7. **[공유 실패 무피드백]** `navigator.share`를 지원하지 않는 브라우저에서 "공유" 버튼을 누르면 아무 동작도 하지 않고 에러 안내도 없다.
8. **[죽은 UI — 프레임 변경 모달을 열 방법이 없음]** `ColorWorkStep3Body`는 "프레임을 바꾸시겠어요?" 확인 모달과 "프레임 수 변경" 바텀시트를 완전히 구현하고 있고, `frameModalStep` prop으로 제어되지만, 두 플로우 컴포넌트(`ColorWorkFlow.tsx`, `ColorWorkResumeFlow.tsx`) 어디에도 `setFrameModalStep("confirm")`을 호출하는 코드가 없다 — grep 결과 전체 코드베이스에서 `"confirm"`으로의 전환 호출이 0건. 즉 이 UI는 **사용자가 실제로는 절대 도달할 수 없는 죽은 코드**다. 업로드 단계 진입 후 레이아웃을 바꾸고 싶으면 상단 뒤로가기(레이아웃 선택 화면으로 완전히 돌아가기)만 가능하다. 의도적으로 미완성 상태로 남겨둔 기능인지, 트리거 버튼을 붙이다가 빠뜨린 것인지 확인이 필요하다.
